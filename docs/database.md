# Схема базы данных

В качестве СУБД используется **PostgreSQL**. Взаимодействие с базой данных происходит через ORM SQLAlchemy.

## Текущее состояние схемы
На данный момент реализованы базовые таблицы для авторизации и разграничения доступа (см. ER-диаграмму ниже). Остальные таблицы находятся в разработке и будут добавлены миграциями к релизу 0.6.

**Реализовано:**
1. **roles** — справочник ролей (Guest, User, Admin).
2. **users** — хранит данные пользователей (email, password_hash, role_id).
3. **recipe_access** — таблица для разграничения доступа к приватным рецептам.

**Запланировано к релизу 0.6 (из ТЗ):**
4. **recipes** — основные данные рецептов (название, описание, автор, приватность).
5. **ingredients** — справочник ингредиентов.
6. **recipe_ingredients** — связь рецептов и ингредиентов (Many-to-Many).
7. **steps** — пошаговые инструкции приготовления.
8. **favorites** — избранные рецепты пользователей (с возможностью хранения личных заметок).
9. **reviews** — отзывы и рейтинги к рецептам.
10. **recipe_history** — история изменений рецептов (позволяет откатывать старые версии).
