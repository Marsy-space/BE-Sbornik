# Правила разработки (Contributing Guidelines)

Данный документ описывает, как мы работаем над проектом «Сборник рецептов», чтобы избежать конфликтов и поддерживать код в чистоте.

## 1. Ветвление (Branching)
* Основная ветка — `main`. Прямые коммиты в `main` **запрещены**.
* Для каждой задачи из Jira создается отдельная ветка. 
* Формат названия ветки:
  * `feature/название-задачи` (для нового функционала, например `feature/add-favorites`)
  * `bugfix/название-бага` (для исправления ошибок)
  * `docs/название-документа` (для документации)

## 2. Коммиты
* Сообщения коммитов должны быть на русском или английском языке, но понятными.
* Пример: `Добавлена модель RecipeHistory`, `Fix: исправлена ошибка 500 при пустом избранном`.

## 3. Процесс Pull Request (PR)
1. Вы создаете PR из своей ветки в `main`.
2. В описании PR вы указываете: какие задачи из Jira закрыты (например, `Closes SCRUM-109`) и что было сделано.
3. **Обязательное правило:** PR должен быть одобрен (Approved) хотя бы одним другим участником команды.
4. После ревью PR сливается в `main` (Merge).

## 4. Стиль кода
* Python-код должен соответствовать стандарту PEP 8.
* Перед пушем желательно запускать линтер (ruff или flake8).
* Переменные и функции именуются в `snake_case`.

## 5. Definition of Done (Критерии готовности задачи)
Задача считается выполненной, если:
* Код написан и работает локально.
* Написаны тесты (если применимо).
* Код прошел ревью.
* Обновлена документация (если требуется).
* Ветка влита в `main`, а задача в Jira переведена в статус Done.
